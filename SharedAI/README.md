# SharedAI R06

Repo-local static contracts and pure capability routing. No service, broker, database reader, secret store, or application runtime dependency.

`catalog/` is authoritative for three approved provider declarations and the two stable model IDs. OpenRouter is provider metadata only; it has no model record or route. Context and capabilities are declarations inherited from the preserved R05 LAB source (1048576 context tokens), not new provider documentation verification or live inference proof. API model strings are independent of stable IDs. `schema/` holds draft-07 contracts; native C# and TypeScript types are mirrored in `generated/`. Strict loaders reject unknown metadata properties, incorrect primitive types, ambiguous identities, credential-bearing endpoints and recognized secret patterns. Arbitrary opaque secret values cannot be identified semantically: catalog review remains necessary. Never supply secret values as metadata.

BlueBrick opts in through `Assistant.SharedAiModelIds`. Config loading adapts the catalog into existing `AssistantModelProfile` instances, retaining the OpenAI-compatible HTTP implementation. No opt-in means the existing profile path remains active. Catalog content copies to the build output and must be included, hashed, and checked in any future deployment manifest. Missing/invalid opted-in catalogs fail closed. The preserved R05 source config is in the R06 evidence directory.

The router filters named ordered routes by declared capabilities and caller-supplied runtime eligibility. Unknown state is ineligible. Vision/tools routes also require their named capability. BlueBrick evaluates process-environment credential presence before sending and retains eligible explicit model selection; default selection prefers Kimi. Streaming requires its declared capability. BlueBrick SharedAI profiles do not use the legacy registry credential fallback. Tool schemas remain gated by `SupportsTools`. Model listings add `RuntimeEligible`, nullable `Available`, `UnavailableReason`, and `AvailabilityEvidence`. Missing credentials return Available=false; present credentials return RuntimeEligible=true and Available=null because authentication/reachability/health remain unknown. User-scope environment presence may differ from an already-running process. Provider health remains unknown in this first adapter.

TypeScript `reconcileAion` accepts only explicit safe projections of AionUI `IProvider` and explicit provider-record bindings. It reports missing/ambiguous mappings, endpoint/context/capability drift, and enablement. It never reads SQLite or encrypted credentials. AionUI `function_calling` maps to tools; missing explicit flags stay unknown. The present AionUI checkout has unresolved merge conflicts; this module is tested independently and is not wired into that application's runtime. Its database and source files remain unchanged. TypeScript validates parsed objects; duplicate raw JSON properties must be rejected by the caller's ingestion boundary (C# rejects them directly).

## Failure boundaries

`Catalog.AllowsFallback` is a policy contract, not an installed transport retry loop. Only provider-boundary credential_missing, provider_unavailable, model_unavailable, rate_limited, and timeout permit consideration of fallback. authentication_failed, malformed_response, unsupported_payload, tool_call_parse_failure, context_limit, and stream_interrupted do not automatically retry. bluebrick_tool_execution_failure, permission rejection, scope rejection, malformed tool results and tool continuation failures never count as provider availability failures.

Preserve the first boundary: request_construction, transport, inference, response_parsing, tool_call_parsing, permission_validation, tool_execution, tool_continuation. Existing R05 transport/error behavior remains authoritative. R06 only implements pre-request credential fallback; post-transport fallback and failure telemetry are NOT_VERIFIED and deliberately not inserted into the tool loop while R05 live compatibility is unresolved. Inference schemas are contracts only, not a forced migration.
